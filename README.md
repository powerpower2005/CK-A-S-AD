# 쿠버네티스 문제집 · CKA / CKS / CKAD

184개 시나리오 안에서 815개 하위 문항을 푸는 정적 웹사이트입니다. 별도로 개인 클러스터에서 수행하는 20개 실습 가이드를 제공합니다. Helm·Kustomize·이미지 빌드·앱 배포를 포함한 워크로드 문제집을 보충했습니다. 배포 결과는 HTML·CSS·JS·JSON·Markdown·YAML뿐이며 백엔드나 데이터베이스가 필요하지 않습니다.

| 과목 | 시나리오 | 하위 문항 |
| --- | ---: | ---: |
| 트러블슈팅 | 70 | 301 |
| 클러스터 | 40 | 200 |
| 스토리지 | 20 | 78 |
| 네트워크 | 42 | 200 |
| 워크로드·배포 | 12 | 36 |

학습 모드는 보기 없는 직접 입력이 기본입니다. “이 문항 제출”로 채점·해설을 확인하거나 작성한 남은 답안을 한 번에 제출합니다. 객관식은 보기 힌트로 전환할 수 있으며, 보기 참고 문항은 ‘도움 없이 회상한 정답’에서 제외됩니다. 결과는 선택한 전체 문항을 분모로 계산합니다. 직접 입력은 등록된 모범 답안·허용 답안의 정규화된 전체 일치만 인정합니다. 핵심어가 들어 있다는 이유로 다른 긴 명령을 정답 처리하지 않습니다. 동등한 다른 표현을 허용하려면 `type.acc`에 명시적으로 추가하세요. 명령 실행·Kubernetes 상태 검증은 아닙니다.

시간 제한 모드는 15·30·60·120분과 시나리오 수를 선택합니다. 직접 입력만 허용하며 종료 전에는 보기·해설·문항별 채점을 제공하지 않습니다. 시간 만료 또는 사용자가 종료할 때 미응답까지 오답으로 채점합니다. 종료 시각은 절대 시각으로 저장하므로 새로고침·탭 이동으로 시간이 초기화되지 않습니다. 실제 시험의 작업 환경·배점을 재현하는 모의고사는 아닙니다.

시험·파트 필터는 해당하는 하위 문항만 선택합니다. 시나리오에 다른 시험 문항이 포함돼 있어도 자동으로 끼워 넣지 않습니다. 원래 시나리오의 일부 단계만 남을 수 있습니다.

## 정적 사이트에서 직접 실행 실습하기

`/labs/`에서 준비 파일, 작업 조건, 검증 명령·예상 결과, 예시 풀이와 정리 명령을 확인합니다. Markdown 가이드와 준비 YAML은 빌드 때 `dist/labs/files/<실습 ID>/`에 생성되는 정적 파일이며 내려받을 수 있습니다.

1. 사용자가 별도 개인 Kubernetes 클러스터와 kubectl을 준비합니다. 예: kind·minikube 또는 이미 가진 연습 클러스터. Windows 예제 명령은 WSL/Linux Bash 기준입니다.
2. 전용 작업 폴더에서 가이드의 준비 명령과 YAML로 초기 상태를 만들고 작업 조건을 직접 해결합니다.
3. 자신의 터미널에서 검증 명령을 실행해 예상 결과와 비교합니다. 사이트의 체크리스트는 본인 확인 기록으로만 저장됩니다.

사이트는 클러스터 접속·명령 실행·자동 실습 채점을 하지 않습니다. kubeconfig나 실행 결과도 수집하지 않습니다. NetworkPolicy는 정책을 강제하는 CNI가, PVC는 기본 StorageClass가 필요합니다. Helm·이미지 빌드는 해당 도구가 추가로 필요하며 각 가이드에 조건을 표시합니다. 예제를 실제 클러스터에서 일괄 실행한 검증은 포함하지 않습니다.

사이트: https://powerpower2005.github.io/CK-A-S-AD/

## 로컬 실행

Node.js 22 이상이 필요합니다. 외부 패키지 설치는 필요하지 않습니다.

```sh
npm run dev
```

`http://127.0.0.1:4173/CK-A-S-AD/`에서 확인합니다. 이 주소는 GitHub Pages의 저장소 하위 경로를 재현합니다. `http://127.0.0.1:4173/`에서도 동작합니다. 파일을 수정한 뒤에는 서버를 종료하고 `npm run dev`를 다시 실행합니다. JSON을 fetch하므로 HTML 파일을 직접 더블클릭하는 대신 HTTP 서버를 사용하세요.

```sh
npm run validate  # 데이터 구조와 ID, 정답 범위, 파트, 문서 URL 검증
npm test          # 모든 과목 채점·오답 거부·필터·저장 복원·종료 시각 검증
npm run build     # 검증 후 dist/에 배포용 파일 생성
```

## 문제 데이터

과목 JSON에는 `schemaVersion: 2`, `parts`, `questions`, `scenarios` 배열이 있습니다. `questions`는 하위 문항이며 기존 ID를 유지합니다. `scenarios`는 다음 필드로 문항을 연결합니다.

| 시나리오 필드 | 의미 |
| --- | --- |
| `id` | 안정적인 식별자 (`case-숫자`) |
| `title` | 과제 이름 |
| `objective` | 과제의 작업 목표 |
| `context` | 공통 상황과 해석 조건 |
| `steps` | 풀이 순서대로 나열한 `questions[].id` 배열 |

모든 하위 문항은 정확히 한 시나리오에 연결되어야 하며, 시나리오마다 최소 두 문항이 있어야 합니다. 각 단계의 조건은 해당 질문에 명시되며, 앞 단계의 오답이 다음 단계의 조건을 바꾸지는 않습니다. 파트·시험 필터는 조건에 맞는 하위 문항만 남겨 시나리오를 구성합니다.

하위 문항 필드는 다음과 같습니다.

| 필드 | 의미 |
| --- | --- |
| `id` | 과목 내에서 유일한 양의 정수 ID |
| `part` | `parts`에 등록된 파트 ID |
| `exam` | `CKA`, `CKS`, `CKAD`, `기타` 중 관련 시험 배열 |
| `tags` | 문항에 표시하는 시험·주제 태그 배열. 공통 문항은 `exam`에 지정한 시험을 모두 포함하며 중복 없이 저장합니다. |
| `title` | 유형 이름 |
| `q` | 질문 본문 |
| `opts` | 보기 4개 |
| `a` | 정답 보기 인덱스: **0부터 시작** |
| `type.p` | 직접 입력 안내 |
| `type.acc` | 직접 입력으로 허용하는 답안 배열 |
| `type.model` | 모범 입력 |
| `exp` | 정답 해설 |
| `whyno` | 오답 보기 해설 3개 |
| `code` | 명령어나 YAML 예제: 줄바꿈은 JSON의 `\n` |
| `trap` | 풀이 팁 |
| `docs` | `[문서 이름, HTTPS URL]` 배열 |
| `freq`, `freqNote` | 원본의 예상 출제 빈도(0~5)와 설명 |
| `curriculum`, `review` | 보충 문항의 공식 학습 영역과 문서 대조·실행 검증 상태 |

`q`, `opts`, `exp`, `whyno`, `trap`, `type.p` 등 기존 서식 필드는 저장소 관리자가 작성한 HTML을 표시합니다. `<code>`, `<b>`, `<p>` 등을 유지할 수 있습니다. `code`와 직접 입력 값은 HTML로 실행되지 않도록 이스케이프합니다. 새 문제의 보기 순서를 바꾸면 `a`도 함께 수정하세요. 원본의 보기 회전 및 허용 답안 보정은 JSON 추출 시 이미 반영했습니다.

문제 ID는 오답 기록에 사용되므로 기존 ID를 다른 문제에 재사용하거나 일괄 재번호 부여하지 마세요. 검토에서 확인된 오류는 수정했으며, 검토 범위와 근거는 `QUESTION_REVIEW.md`에 있습니다. 모든 예제를 실제 Kubernetes 클러스터에서 실행한 것은 아닙니다.

## 저장과 사용 범위

오답은 `ck-a-s-ad:v1:<과목 ID>:wrong` 키로 이 브라우저의 `localStorage`에 저장합니다. 정답을 맞히면 오답노트에서 빠집니다. 테마는 모든 과목이 공유합니다. 저장소 접근이 제한된 브라우저에서도 현재 세션의 풀이는 가능합니다.

진행 중 풀이 순서·답안·채점 결과·보기 참고 여부·시간 제한은 `ck-a-s-ad:v2:<과목 ID>:session`에 자동 저장합니다. 새로고침 시 이전 풀이 화면을 복원합니다. 문제 내용이나 시나리오 연결이 바뀌면 호환되지 않는 진행 기록은 복원하지 않습니다. 설정 변경만으로 저장된 풀이를 덮어쓰지 않으며, 새 학습을 시작할 때 교체합니다. 실습 자가 확인은 `ck-a-s-ad:v1:labs:checks`에 저장하고 가이드 조건이 바뀌면 해당 체크를 초기화합니다.

다른 기기와 동기화되지는 않습니다. 기존 다운로드 HTML의 `file://` 오답 기록도 새 HTTPS 사이트로 자동 이동하지 않습니다. 저장소 접근이 불가능하면 현재 탭에서만 유지됨을 표시합니다. 글꼴은 Google Fonts를 사용하며 연결되지 않으면 시스템 글꼴로 표시합니다.

## GitHub Pages 배포

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
2. GitHub Actions가 저장소에서 허용되어 있어야 합니다.
3. `main`에 변경 사항을 push하면 `.github/workflows/pages.yml`이 데이터를 검증하고 `dist/`를 배포합니다.
4. 배포 상태는 저장소의 **Actions** 탭에서 확인합니다. Pull request에서는 검증과 빌드만 수행합니다.

배포에 필요한 `contents: read`, `pages: write`, `id-token: write` 권한은 workflow에 선언되어 있습니다. 별도 개인 토큰이나 Secrets는 필요하지 않습니다. 저장소 전체의 기본 workflow 권한을 쓰기 권한으로 변경할 필요도 없습니다.

저장소 이름을 바꾸면 `404.html`의 홈 링크와 `scripts/serve.mjs`의 미리보기 경로도 변경하세요. 일반 페이지 링크는 상대 위치를 사용합니다.
